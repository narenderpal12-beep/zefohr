# PROJECT: Editable marketing website + organisation sign-up portal for an Indian HRMS product (PHASE 1)

Build a full-stack, SEO-friendly marketing website where EVERY piece of content is editable from an admin panel, and where organisations can register for a free trial or a paid subscription. A separate multi-module HRMS web app will be added later (PHASE 2), so architect for it now. Build Phase 1 only.

## 1. TECH STACK
- Frontend: React 18 + Vite (JavaScript), react-router-dom, framer-motion, lottie-react, lucide-react, react-helmet-async
- Backend: Node.js + Express (ES modules), REST API under /api/v1
- Database: PostgreSQL (Replit Postgres via DATABASE_URL) with `pg` and plain SQL migrations
- Auth: JWT (7-day), bcryptjs, helmet, cors, express-rate-limit, compression
- Rendering: Vite SSR with Express (see section 9) so public pages are crawlable
- Single deployable app: in production Express serves the built client and server-renders public routes
- Vite dev server: host 0.0.0.0, allowedHosts: true, proxy /api to the Express port
- Layout: /client, /server (src/routes, src/modules, src/db, src/payments, migrations), root package.json scripts: dev (concurrently), build, start, db:migrate, db:seed, db:setup
- Env (Replit Secrets): PORT, DATABASE_URL, JWT_SECRET, SUPER_ADMIN_EMAIL, SUPER_ADMIN_PASSWORD, SITE_URL

## 2. DESIGN & ANIMATION (must look premium)
- Modern dark theme with gradient accents (indigo / cyan / pink), glassmorphism cards, animated aurora blobs behind the hero, gradient headline text.
- Hero with a Lottie animation (bundled default orbit/people animation; the Lottie URL is editable in admin) plus floating animated cards.
- Framer Motion: scroll-reveal with stagger, animated counters for stats, hover tilt/glow on cards, animated tabs, FAQ accordion with AnimatePresence, pricing toggle (monthly/annual), page fade transitions, infinite marquee for integrations.
- Lottie success animation after registration.
- Fully responsive, mobile menu, accessible, respects prefers-reduced-motion.
- Animations must never hide content from crawlers: content is present in the server HTML, and animation only enhances it after hydration.

## 3. EVERYTHING EDITABLE (CMS)
- Table `site_content(key text pk, value jsonb, updated_at, updated_by)` plus `site_content_history` for versioning.
- Every section reads from it: nav, hero, stats, suites, specialised services, ai, whyUs, integrations, pricing, faq, contact, footer, theme (colours), register page text, dashboard text, roadmap.
- API: GET /content (public; merges DB over built-in defaults so the site works even before seeding), PUT /content/:key (super_admin), POST /content/:key/reset, GET /content/:key/history.
- Admin panel at /admin (super_admin only) with a generic recursive form editor generated from the JSON (inputs, textareas, numbers, booleans, arrays with add/remove/reorder, nested objects) plus a "Raw JSON" tab, Save, Reset to default and "Saved" feedback.
- Theme colours, icon names (from a fixed lucide icon map), Lottie URL, prices and trial days are all editable. Changes show on the live site immediately, with no redeploy.
- Admin tabs: Content, Pages, Blog Posts, SEO Manager, Organisations (list, change subscription status/plan/trial end), Leads (contact form submissions), Redirects.

## 5. ORGANISATION REGISTRATION (trial + subscription)
- `/register` form: organisation name, industry, size band, employee count, phone, optional GST number, admin name, email, password (+confirm), plan (cards from pricing content), mode toggle "Free trial" or "Subscribe", billing cycle (monthly/annual, for subscribe), terms checkbox. Prefill from query params ?plan= and ?mode=.
- `POST /auth/register-organisation` (single transaction): creates the organisation (slug), an org_admin user, a subscription, and enables the modules of the chosen plan.
  - Trial = status 'trial', trial_ends_at = now + pricing.trialDays (default 14, editable).
  - Subscribe = status 'pending_payment'.
- Subscription statuses: trial, pending_payment, active, past_due, cancelled, expired. Lazily mark trials expired once trial_ends_at has passed.
- Payment gateway: build a clean abstraction (`server/src/payments/provider.js`) with a stub provider and clear TODOs for Razorpay (orders, webhook, signature verification). Do NOT fake successful payments; admin can mark a subscription active manually.
- `/dashboard` shows the organisation, a subscription card (plan, status, days left in trial), an upgrade/subscribe action, the list of enabled and locked modules, and a "HRMS app coming soon" panel with an editable roadmap.
- Auth endpoints: POST /auth/login, GET /auth/me (user + organisation + subscription + modules). Roles: super_admin, org_admin, hr_manager, employee. Email unique (case-insensitive). Rate-limit auth routes. Validate all input server-side.

## 7. SEO MANAGER (admin page to edit SEO for the WHOLE website, now and in future)
Build `/admin/seo` (super_admin only). It must cover every public page automatically, including any page, blog post, suite, service or future HRMS marketing page added later, with no code changes.

### Automatic page discovery (future-proof)
- A server route registry, `registerSeoRoute({ path, type, titleFrom, descFrom })`, lets any new module, page, post, suite or service register itself. New pages appear in the SEO Manager automatically with defaults generated from page content.
- Fallback chain when a field is empty: page value, then content-derived default, then global default template. SEO output is never blank.
- Support dynamic patterns (/blog/:slug, /features/:slug) with a pattern-level default plus per-URL overrides.
- Reserve the `app_public` page type for future HRMS marketing pages so they use the same system.

### SEO Manager UI
1. Dashboard: table of all pages with path, type, title, description length, index status, in sitemap, SEO score. Search, filter by type/status/issue, bulk edit (noindex, sitemap include, schema type), CSV export and import.
2. Page editor: all seo_pages fields, live character counters (title ≤60, description ≤160), a Google search result preview, a social share preview (Facebook/LinkedIn/X), and a checklist (one H1, focus keyword in title/description/H1, image alt text, internal links, canonical set). Shows a 0–100 score with fix suggestions.
3. Global settings tab: all seo_settings fields. GA4 and verification tags are injected into the head automatically.
4. Schema tab: edit Organization/WebSite JSON-LD, choose schema type per page, edit FAQ items for FAQPage schema, validate JSON before saving.
5. Sitemap & robots tab: preview the generated /sitemap.xml (sitemap index when over 50,000 URLs) and /robots.txt, toggle pages in or out, edit robots rules.
6. Redirects tab: add, import and test 301/302 redirects, detect loops, show hit counts.
7. 404 monitor: log unknown URLs hit by visitors and crawlers, with a one-click "create redirect".
8. History: view and restore previous versions for any page.

### SEO API
- GET/PUT /api/v1/seo/settings
- GET /api/v1/seo/pages (filter, paginate), GET/PUT /api/v1/seo/pages/:id, POST /api/v1/seo/pages/bulk
- GET/POST/PUT/DELETE /api/v1/seo/redirects
- Public GET /api/v1/seo/resolve?path=/x returns the final merged SEO for a path. It is used by the server renderer, cached in memory, and invalidated whenever SEO is edited.

### Rules
- Authenticated areas (/admin, /dashboard, /login, /register and any future HRMS app routes) are forced to noindex by default and cannot be set to index without an explicit override.
- Only super_admin can edit. Log every change to audit_log. Sanitise extra_head_html and custom JSON-LD, and warn before setting noindex on an important page.

## 9. SEO & RENDERING (public pages must be crawlable)
### Rendering
- Use Vite SSR with Express: `entry-server.jsx` (renderToString with StaticRouter) and `entry-client.jsx` (hydrateRoot). In production Express renders each public route with CMS content already loaded, so crawlers receive full HTML.
- Dev: Vite middleware mode. Prod: serve built client assets and render via the server bundle.
- Guard browser-only code: load lottie-react client-only (React.lazy) with a static placeholder on the server. Never touch window or localStorage during render.
- Fallback if SSR proves too complex: Express injects per-route title, meta, canonical, Open Graph and JSON-LD into index.html, plus a build-time prerender script that outputs static HTML for all public routes. Public pages must never be blank before JavaScript runs.

### Technical SEO
- The server renderer calls /seo/resolve for every request and outputs title, meta description, canonical, robots, Open Graph, Twitter tags and JSON-LD in the HTML. `lang="en-IN"`.
- JSON-LD: Organization + WebSite on all pages, SoftwareApplication + Offer on pricing, FAQPage on FAQ and suite pages, BreadcrumbList on inner pages, Article on blog posts.
- Dynamic /sitemap.xml (CMS pages, suites, services, published posts, with lastmod) and dynamic /robots.txt (disallow /admin, /dashboard, /api; link the sitemap).
- Clean URLs, one H1 per page with logical H2/H3 hierarchy, semantic HTML (header, nav, main, section, article, footer), breadcrumbs and descriptive internal links. Redirect table applied before routing, with real 404 status for unknown URLs.
- Images: width/height set, lazy loading, editable alt text, WebP/AVIF where possible. font-display: swap.
- Core Web Vitals targets: LCP < 2.5s, CLS < 0.1, INP < 200ms. Code-split routes, lazy-load Lottie and below-the-fold animations, gzip/brotli, long-cache headers for hashed assets.
- Default share image (editable) used when a page has no OG image.

## 11. ACCEPTANCE CRITERIA
1. `npm run db:setup && npm run dev` works on Replit with a fresh Postgres.
2. The home page and all inner pages render from CMS content. Editing any field in /admin updates the live site with no redeploy.
3. A visitor can register an organisation in trial mode and in subscribe mode. Correct subscription rows and enabled modules are created, and duplicate emails are rejected.
4. Super admin can edit all content, create pages and blog posts, reset a section, view organisations and leads, and change a subscription status.
5. "View source" on /, /features/payroll-and-compliance and /pricing shows full content, a unique title and description, canonical and JSON-LD without running JavaScript.
6. Creating a new page, post, suite or service makes it appear in /admin/seo within seconds with auto-generated default SEO. Editing its SEO changes the rendered HTML immediately.
7. /sitemap.xml lists all indexable public pages and published posts. /robots.txt blocks /admin, /dashboard and /api. A noindex page is excluded from the sitemap.
8. Unknown URLs return HTTP 404, and configured redirects return the correct 301/302.
9. SEO history can restore a previous state for any page.
10. Animations (Lottie, Framer Motion, aurora, marquee, counters) run smoothly on desktop and mobile. Lighthouse on mobile for the home page: SEO ≥ 95, Accessibility ≥ 90, Performance ≥ 85.
